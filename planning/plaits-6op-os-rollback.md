# Plaits 6-op OS attempt — rollback postmortem

> **2026-05-16 RETROACTIVE NOTE**: The crashes documented below were
> almost certainly NOT caused by the OS-related code changes
> (templating Voice<>::Render, inlining FMVoice::Render, class-member
> os_buffer_). They were the same Cortex-A8 AAPCS NEON spill issue
> that was independently isolated the next day and fixed at mi 1.0.3.13
> with `mi_barrier_noop()` (see `planning/mi-mode-switch-aapcs-barrier-resolution.md`
> and memory `feedback_neon_aapcs_call_barrier`). Smoking gun: 1.0.3.3
> set `kSixOpOversampling = 1` (no OS work at all, just kept the
> structural infrastructure) and STILL crashed. That's exactly the
> baseline 1.0.3.4 behavior post-rollback — also crashed without the
> AAPCS barrier.
>
> **Re-attempted at mi 1.0.3.16** with a minimal-risk approach
> (entire OS implementation contained inside `SixOpEngine::Render`,
> no template/inline/class-member changes to fm::Voice). All four
> rollback "lessons" about what NOT to touch are still followed by
> .16 — not because they were validated, but because they're
> orthogonal to the surgical fix this re-attempt uses.

Session 2026-05-15. Attempted to add 2× oversampling to Plaits' 6-op
FM engine to fix DX7-style aliasing noise. **Aborted after 4 ship
versions failed** — every attempt crashed on engine/algorithm
switch on Cortex-A8 hardware (loaded fine in emu).

## Versions tried & failure mode

| Version | Change | Result |
|---|---|---|
| **1.0.3** (first attempt) | Voice<>::Render gained runtime `int oversampling=1` parameter; SixOpEngine added `os_buffer_*` arena pointer; per-sample OS render + 2-tap MA decimate | **Heap corruption on load** — PlaitsVoice.cpp wasn't rebuilt by `make` despite header edits (transitive header deps untracked), so PlaitsVoice.o had OLD sizeof(plaits::Voice) while six_op_engine.o had NEW sizeof — writes past allocation |
| **1.0.3 (force-cleaned rebuild)** | Same code, all .o rebuilt | **Loaded but crashed on engine/algorithm switch** on hardware |
| **1.0.3.1** | Version bump only (forces re-extract on rear SD) | Same crash (confirmed not a stale-extraction issue) |
| **1.0.3.2** | Moved `os_buffer_` from arena allocation to class member `float os_buffer_[kOsBufferSize]` (to avoid arena overlap risk per `plaits::Voice::Init`'s shared-RAM trick) | Still crashes on engine switch |
| **1.0.3.3** | `kSixOpOversampling = 1` (no actual OS work — bisect diagnostic; template + class-member + decimate-loop infrastructure all preserved) | **Still crashes** — proves the OS work itself is NOT the trigger; trigger is structural in the rest of the changes |

## What was investigated and ruled OUT

- **SWIG wrapper staleness** (`feedback_swig_header_dep`): `mods/mi/mi_swig.cpp` was regenerated by the new `SWIG_HEADER_DEPS` rule; SWIG-side is clean. Not the trigger.
- **stmlib ARM inline asm `ssat`/`usat`/`vsqrt.f32` crash** (per `docs/knowledge-base.md:18-19`): `-DTEST` IS passed to noise_engine.cc / particle_engine.cc / snare_drum_engine.cc compilation (verified via `make -n` output) — the C fallback path is active. Compiled `vsqrt.f32` instructions in libmi.so come from libm `sqrtf` inlined under `-O3 -ffast-math`, not the inline asm — that's been there since well before this session and doesn't trigger crashes. Not the trigger.
- **Arena overlap from added arena allocation** (`plaits::Voice::Init`'s shared-RAM pattern): addressed in 1.0.3.2 by moving `os_buffer_` to class member entirely. Crash persists. Not the trigger.
- **Runtime-branched DSP dispatch** (`feedback_runtime_branched_dsp_dispatch`): addressed by converting `oversampling` from runtime `int` parameter to compile-time `template <int Oversampling>` parameter. Crash persists. Per the disassembly, this DID eliminate the `Pfji` out-of-line symbol so the runtime param is structurally gone. Not the trigger (or not the full trigger).
- **OS-render itself** (per 1.0.3.3 bisect): `kSixOpOversampling=1` with everything else intact still crashes. Not the trigger.

## What remained suspect when rollback was called

The trigger is in the structural changes that DIDN'T get bisected:

1. **`Voice<num_operators>::Render` template conversion** — adding `template <int Oversampling=1>` to all three Render overloads. Even with OS=1 default, the template instantiation may interact with the algorithm function-pointer dispatch table differently than the original non-template form.
2. **`FMVoice::Render` inlined into header as template** — was an out-of-line method in .cc previously; now an inline template body in .h. Symbol no longer exists; everything's inlined into `SixOpEngine::Render` (which grew from ~2KB to ~10.7KB). The aggressive inlining + ~5x larger function body may interact with Cortex-A8 prefetcher / I-cache in ways the original layout didn't.
3. **Class-member `os_buffer_[288]` increasing sizeof(SixOpEngine) by 1152 bytes** — shifts memory layout of all subsequent members of `plaits::Voice`. While each engine re-inits on switch (per the `8058cd2` "fix engine switch crash" commit's mechanism), the shifted layout may interact with hardcoded offsets somewhere (algorithm tables, render call tables?) that I haven't audited.

None of these were individually bisected because the rollback was called before exhausting the bisect tree.

## Lessons for any future attempt at this work

1. **Don't extend Plaits engine structs with class members.** The shared-arena trick + engine re-init pattern in `plaits::Voice::Render` is fragile to memory layout changes. If you need extra scratch for an engine, allocate it from the arena (and ACCEPT the arena overlap with other engines, since the re-init fix takes care of it for the active engine).
2. **Don't template the existing `Voice<>::Render`.** Even though the template-vs-runtime-parameter distinction is principled (per `feedback_runtime_branched_dsp_dispatch`), the rest of Plaits' algorithm-dispatch machinery wasn't built with template-instantiation-induced inlining in mind. The aggressive inlining changes function body sizes in ways that hit Cortex-A8 codegen sensitivities.
3. **Don't inline `FMVoice::Render` into the header.** Keeping it out-of-line preserves symbol boundaries the codebase has tested against.
4. **If you need OS for 6-op specifically, do it WITHOUT touching `Voice<>::Render`.** Possible approaches:
   - Wrap voice.Render externally — render at 1× rate twice with offset call patterns
   - Add a post-Render anti-alias filter on the output (cheap LP at ~16kHz) — doesn't fix true aliasing but masks the noise
   - Use per-operator hf_taming similar to classic 2-op fm_engine.cc — limits modulation index based on frequency
5. **Bisect smaller next time.** This session shipped 4 versions before bisecting. Single-axis bisect (revert template, revert class member, revert os_buffer usage) would have isolated the trigger faster than ship-and-test cycles.
6. **The "engine switch crash" sensitivity in Plaits is real.** Commit `8058cd2` already documented this for arena re-init. Treat any modification to Plaits' Voice / Engine class layouts or method signatures as audition-critical.
